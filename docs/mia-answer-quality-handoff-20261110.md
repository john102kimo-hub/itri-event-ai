## 一、結論

**截圖那兩則，米亞沒有答錯。問題是「答對了，卻讓人更火大」。** 顧問文件把壞答案分成四種（群組觸發、路由、知識庫沒寫、模型讀錯），這是第五種：**講法**。它不是模型的個性問題，程式裡找得到五個具體成因：

| # | 成因 | 在哪裡 |
|---|---|---|
| 1 | 那句話是我們自己教的。規則直接給了台詞「這部分我沒有資料，建議洽現場新聞聯絡人」，LINE 規則再講一次，語氣規則還要求「直接、明確地說沒有」。模型是照做。 | `lib/prompt.js` `buildSystemPrompt()` 第 2 條規則；`lib/line-format.js` `lineExtraRules()` 的 `contactHint`、`TONE_RULE` 最後一句 |
| 2 | 「沒有資料」把三件不同的事講成同一句：**資料沒寫**（公關補得了）、**院方還沒決定或不便說明**（補不了，只能講口徑）、**不在米亞職責內**。聲明稿這種場合，第二種被說成「我沒有資料」最刺耳，因為院方當然有資料。 | 同上，規則沒有區分 |
| 3 | 答不出來是死路。米亞說「請洽朱則瑋」，但朱則瑋不知道有人被擋下來。即時通知只有記者自己打「找真人」才會發；待教清單一天掃一次。 | `lib/line-reporter.js` `sendHumanContact()`（有通知）對照 `answerQuestion()`（沒有）；`vercel.json` 的 `cron_teach` |
| 4 | 連續追問時，第二則把同一套話再講一遍，再掛一次警語。真人被追問第二次會換講法、直接給電話。 | `answerQuestion()` 不知道上一題也是答不出來 |
| 5 | 答不出來時會自動去官網新聞中心補查。這兩題剛好沒查到；關鍵詞如果抽成「院士」，後面就會接上「不過我在工研院官網新聞中心找到了：院士授證典禮…」。爭議事件裡這是火上加油。 | `answerQuestion()` 裡 `NO_DATA_PHRASE_RE` → `itriNewsHintBlock()` |

**不能只改 prompt 的措辭。** 「沒有資料」這幾個字同時是三個機制的開關：補查官網（`NO_DATA_PHRASE_RE`）、後台「疑似答不出來」與待教清單（`UNANSWERED_RE`，`api/analytics.js`、`lib/teach-queue.js`、`lib/assistant.js` 共用）、評測的 `honest_no_data`（`tools/eval/checks.mjs`）。措辭一換，三個一起瞎掉。所以順序是：**先把「這一題答得怎麼樣」從措辭裡拆出來變成一欄資料（工單 A），再改講法（工單 B）。**

**母資料庫：要做，但做小的，而且它救不了截圖這種題目。** 細節在第四節。截圖那種「口徑以外的追問」，真正有效的是公關事先寫好的**預擬問答**與**口徑外固定句**（工單 B4），不是資料庫。

**建議順序：0（測試基準）→ A → B → C（母資料庫）→ D、E 看 A 的數據再決定。**

## 二、截圖逐句看

第二張截圖的回覆：

> 這部分我沒有資料，無法確認是否正在討論，也不能說有或沒有。目前能對外說明的只有官方聲明稿的內容，聲明稿沒有提到撤銷院士的任何程序或進度。建議直接洽工研院公關，或新聞聯絡人 朱則瑋，以他們的說法為準。內容僅供參考，以工研院官網新聞稿或發言為準。

| 原句 | 記者讀到的意思 | 真人公關會怎麼處理 |
|---|---|---|
| 這部分我沒有資料 | 你們在裝傻 | 講成自己的角色界線：「這一點我不方便替院方多做解讀」 |
| 無法確認…也不能說有或沒有 | 連續三個否定，像在念法務稿 | 一句就好，而且先接住對方：「了解，您想確認的是後續會不會有進一步處理」 |
| 建議直接洽…朱則瑋 | 把我踢給別人，而且那個人不知道我要找他 | 「這題我已經轉給朱則瑋了」＋電話。**先做再說** |
| 內容僅供參考… | 你什麼都沒說，還僅供參考 | 純粹答不出來的回覆，警語是雜訊（要不要省略請朱朱決定，見第六節） |

目標長相（當初的示意；**朱朱已改成「先問要不要轉介」，定稿句子見第〇節**）：

> 了解，您想確認的是後續會不會有進一步處理。
> 這一點院方目前對外的說明就到聲明稿為止，我不方便替院方多做解讀，怕誤導您。
>
> 這題我已經轉給公關同仁了，他們看到會直接在這裡回您；趕稿的話直接打給新聞聯絡人比較快：朱則瑋 09xx-xxx-xxx

四個零件：**接住**（用對方的話複述他要確認的事）→ **能說的先說** → **界線講成「我的角色」而不是「沒有資料」** → **下一步是「我做了什麼」而不是「你去找誰」**。

三條不能因為要有溫度而鬆掉的線：

- **不代表院方道歉、承諾、評論**（`buildSystemPrompt()` 現有規則）。同理的對象是「記者要趕稿」，不是事件本身。
- **不推測**。第一張截圖那句「也請不要解讀成『不撤銷』」功能是對的（防止被寫成「工研院：不會撤銷」），要留，只是換個不像在教訓人的講法，例如「我這樣說不代表院方的決定是或不是」。
- **有溫度不等於多話**。三到四行，不要連說三次抱歉。

## 四、母資料庫：要不要做、做成什麼樣

**現在其實已經有兩塊種子**，所以不是從零開始：

- `bot_memory` 的全站事實：同仁打「全站記住：…」就會接進每一場的答題 prompt（`lib/bot-memory.js` `formatFactBlock()`）。限制是每條 200 字、最多 40 條、後台看不到。
- `contacts_directory`：全站技術窗口表，一格存整份、後台一個 textarea 編輯。

**它解決什麼：**

1. **沒綁活動時的機構題**。現在記者問「怎麼申請採訪」「工研院有幾個所」，四條路都對不上，走到 `composeFallbackReply()`，而那支被明令「不要提供任何事實內容」，只能回功能選單。這是母資料庫最有價值的地方。
2. 場次知識庫沒寫、但機構層有答案的題目。
3. 名稱對照（中文全名／縮寫／英文名），順便降低 `answer-grounding` 的英文名詞誤報。

**它不解決什麼：** 問 A 答 B（那是路由）、截圖那種口徑外追問（那是預擬問答）、「不要亂說」這類規則（那是出口）。

**建議的 v1 規格**（工單 C）：

- **存哪**：Sheets 新分頁 `org_kb`，一格存整份，比照 `contacts_directory`。後台編輯走 `api/events.js` 加 action，**不開新的 API 檔**（Function 已經 11／12，見 LINE-PLAN.md 坑 2）。
- **放什麼**：機構簡介與各所領域、非活動專屬的常見問答（採訪申請、參訪、授權洽談找誰）、名稱對照。每一條前面寫更新日期。
- **不放**：會變的數字、任何規則、未公開的東西。
- **大小**：6,000 字以內，所以**不需要檢索**，整份帶進 prompt 就好（跟坑 7 一致）。
- **怎麼用**：
  - 綁定中：接在 LINE 答題 prompt 的 `factBlock` 後面（那一塊吃快取，成本很低），標題寫明「機構一般資料：這一場的資料沒寫到才用，用了要說明這是工研院一般公開資料」。優先順序：**這一場的知識庫 ＞ 同仁補充 ＞ 機構資料**；說法不同就並列（坑 6）。
  - 沒綁定：`routeIntent()` 加一個意圖 `org_faq`，新寫一支 `answerOrgFaq()` 只拿 `org_kb` 回答，出口照樣走 `askAnthropic()`（繁體、Markdown 清理都在那裡）。
  - 企業場、敏感場次不帶。
- **維護**：超過 180 天沒更新的條目，在後台標出來。過期的機構資料等於替主辦單位講錯話。
- **紀錄**：用到機構資料時，`kb_source` 記 `org`（工單 A 的欄位）。

### 工單 A：把每一題的決策記下來（最優先）

**為什麼先做**：沒有它，工單 B 一改措辭，後台的「疑似答不出來」、待教清單、評測都會失準；也沒辦法判斷壞答案壞在哪一關。

**現況比顧問文件寫的更糟一點**：LINE 只有活動問答會寫 `qa_log`（`lib/line-reporter.js` 的 `logQa()`，全檔只有 `answerQuestion()` 呼叫）。產業趨勢、工研院技術、活動清單、兜底引導這幾條路**完全沒有紀錄**。記者問活動卻被判去產業趨勢，後台看不到這一題存在過。

**做法：**

1. **`qa_log` 從 J 欄往後加欄位**（A–I 不動）：
   `answer_status`（`answered`／`no_data`／`no_data_news`／`refused`／`contact`）、`intent`、`routed_event_ids`、`confidence`、`context_source`（`1:1` 或 `group`；綁定／發問者自己上一題／路由自動換場／代碼／按鈕）、`kb_source`（`kb`／`invite`／`related:<ids>`／`news`／`org`）、`no_data_keyword`、`grounding_flags`。
   動工前先確認每個讀取點都是寫死範圍：`grep -rn "qa_log!" api lib tools`（目前都是 `A2:I`、`A2:H`、`A:E`＋`G:I`，加欄位不會被誤讀）。
2. **新分頁 `route_log`**：米亞有回、但沒進 `qa_log` 的訊息各寫一列（時間、1:1 或群組、intent、選到的場次、confidence、走了哪條路、問題前 60 字）。**群組裡米亞保持安靜的訊息不記**（那是別人的聊天）。
3. **怎麼把路由結果帶到寫入點**：不要改六個呼叫端的參數。`lib/line-runtime.js` 已經有 `requestCtx`（AsyncLocalStorage），`api/line.js` 的 handler 每則事件會重設 `quoteToken`；在同一個地方加一個每則事件重設的 `trace` 物件，`routeIntent()` 回來後（`api/line.js` `handleEvent()`、`lib/line-reporter.js` `handleUnbound()`、`lib/line-group.js` `handleGroupMessage()` 三處）寫進去，`logQa()` 讀出來。
4. **`answer_status` 在 `answerQuestion()` 算**：`refused` → `refused`；有 `noDataKeyword` 或 `phraseHit` → `no_data`（補查有命中就 `no_data_news`）；命中邀訪窗口 → `contact`；其餘 `answered`。
5. **讀取端改看欄位**：在 `lib/teach-queue.js` 加一支 `isUnansweredRow(row)`——J 欄有值就看 J 欄，沒有（舊資料）才退回 `UNANSWERED_RE`。`api/analytics.js`、`lib/assistant.js`、`findSuspects()` 都改用它。讀取範圍跟著放寬到 J 欄。
6. 網頁版 `api/chat.js` `logQA()` 寫同一組欄位（網頁沒有路由，`intent` 固定 `qa`）。
7. 後台匯出 CSV（`api/export.js`）帶出新欄位。

**驗收：** 隨便問 5 題（活動、產業趨勢、技術、閒聊、一題答不出來的），`qa_log` 與 `route_log` 合起來剛好 5 列，每列看得出判成什麼、選哪一場、用哪份資料。寫入失敗不擋回覆（沿用現有 try/catch）。`node test/run-all.mjs` 全過。

**不要做：** 不要把路由紀錄寫進 `qa_log` 當一題（後台「累積回答題數」會灌水，批次紀錄裡修過這件事）。

### 工單 B：答不出來時的講法

前置：工單 A 完成。動工前先跑評測基準（`tools/eval/README.md` 的 ①）。

**B1　prompt：三種「答不出來」分開講**

- `buildSystemPrompt()` 不帶參數時的輸出要跟網頁版逐 byte 相同（`test/test-prompt.mjs`、`test/test-batch118.mjs` 會擋）。**不要用「再加一條規則去蓋掉前一條」的方式**（兩條規則搶同一件事，這個專案踩過）。建議給 `buildSystemPrompt()`／`buildBusinessSystemPrompt()` 加一個選填參數替換第 2 條規則的文字，預設值維持原字串；LINE 傳自己的版本進去。
- LINE 版的規則改成分三種情況：
  - **資料沒寫**（這場該有、但知識庫沒寫的名單、時間、數字）：說「這個我手上的資料還沒寫到」。
  - **口徑以外**（院方尚未決定、不評論、聲明稿範圍外的追問、要求解讀立場）：說「院方目前對外的說明就到這裡，我不方便替院方多做解讀」。知識庫裡有【口徑外的問題】段落時，照那一段的原文講（見 B4）。
  - **離題或立場評論**：沿用現有婉拒規則。
- 三種都用同一個形狀：先用對方的話接住 → 能說的先說 → 講界線 → 停。**不要自己寫「建議洽某某」「我幫您轉達」**，程式會接（B2）。寫法比照 `GROUP_ANSWER_RULE`「程式會在後面自動附上，你不用自己寫」。
- `TONE_RULE` 最後一句（「查不到…直接、明確地說沒有」）與 `contactHint` 跟著改寫。
- `[[NO_DATA:關鍵詞]]` 標記規則留著，但觸發條件的描述從「只要你這則回覆裡出現『這部分我沒有資料』這類說法」改成**看狀態、不看措辭**：「記者問的那一項你沒有給出來，不管你怎麼措辭」。口徑以外的情況請模型把關鍵詞填成固定字 `口徑外`，程式拿來分辨（B3 要用）。
- `NO_DATA_PHRASE_RE` 是標記沒出現時的第二道網，補上新講法會出現的字（「資料還沒寫到」「對外的說明就到」「不方便替院方」）。`tools/eval/checks.mjs` 的 `FALLBACK_NO_DATA_RE` 是同一條的備份，一起改。

**B2　程式接上的尾巴（保證是真的）**

> ⚠️ 這一段的做法已被批次 197 取代：不是自動通知，是先問記者、回「是」才通知。見第〇節。

`answerQuestion()` 在 `answer_status` 是 `no_data` 時：

1. 推播通知管理員（`LINE_ADMIN_USER_ID`），有活動負責人就一併通知（`lib/event-owner.js`）。內容：哪一場、1:1 或群組、原話前 100 字。可以直接抽用 `sendHumanContact()` 裡那段。
2. 推播成功才接：「這題我已經轉給公關同仁了，他們看到會直接在這裡回您；趕稿的話直接打給新聞聯絡人比較快：{press_contact}」。沒成功或沒設定就只接聯絡人那半句。**不承諾時間**（LINE-PLAN.md 第 9 節第 3 條；這句沿用 `sendHumanContact()` 已經審過的說法）。
3. 群組裡的說法要另外想：同仁能不能在群組直接回，取決於 LINE 官方帳號後台的設定，先確認再寫句子。
4. 一定要有上限。推播額度全帳號共用（記者、業發處、提醒都在用）：同一個對話 10 分鐘內只通知一次，每場每小時、全站每天各設上限，超過就只記不推。上限值請朱朱決定。
5. 這條尾巴不進對話歷史（比照 `switchNotice`、`groundingNote`）。

**B3　連續追問**

上一題的 `answer_status` 也是 `no_data`、同一場、10 分鐘內 → 這一題：

- 在 `extraSystem` 加一句提示：「上一題你已經說明過院方的說明到此為止，這一題不要重複同一套話，兩行以內」。
- 尾巴換成升級版：「這幾題都超出我能說的範圍，再問我也是一樣的答案，不想耽誤您時間。直接找 {press_contact} 最快，您的問題我都轉給他了。」
- 需要在上一輪記憶裡多存一個狀態：`lib/line-store.js` 的 `setRecentTurn()`／`setGroupTurn()` 目前存 `{t,e,q,a}`，加一個 `s`。

**B4　敏感場次（聲明稿、回應說明）**

- 新增一份明確的活動類型清單（寫法比照 `lib/audience.js` 的 `BUSINESS_EVENT_TYPES`，不要用「名稱含某字就算」）。類型名稱請朱朱決定，例如「聲明」「回應說明」。
- 這種場次在程式裡固定：**不補查官網**（跳過 `itriNewsHintBlock()`）、**不帶跨場次資料**（跳過 `selectRelatedEvents()`）、**不帶機構資料**、每一題 `no_data` 都通知（上限照 B2）。
- **不要加 `events` 表欄位**（`lib/event-owner.js` 檔頭寫了原因：A–R 欄在很多地方寫死）。口徑放知識庫裡：`lib/kb-template.js` 已經有【常見問答 Q&A】；敏感場次的範本多一段【口徑外的問題】，公關寫一句固定說法。程式用現有的分段函式把這一段取出來，`no_data` 而且關鍵詞是 `口徑外` 時**原樣接上**，不經模型改寫。
- 發布前檢查（`lib/event-status.js` `eventChecklist()`、`.claude/skills/new-event-checklist`）：敏感場次沒有預擬問答、沒有口徑外固定句、沒有新聞聯絡人電話 → 提醒。
- 預擬問答從哪來：媒體訓練（`api/training.js`）本來就會模擬記者提問。可以加一顆「幫我預想記者會追問什麼」，產出 10 題給公關填答案再貼進知識庫。這顆不急，先確定有人要用。

**B5　其他固定句的文案**

這幾句不經模型、同樣是記者會看到的死路，照同一個形狀改寫，定稿請朱朱審：

- `lib/ai-refusal.js` `refusalReply()`：「這一題我這邊沒辦法回答，建議直接洽新聞聯絡人」。⚠️ `isRefusalReply()` 是整句比對，文字要一起改，`test/test-batch134.mjs` 也要跟著動。

**B6　評測與測試**

- `tools/eval/cases/` 加一個虛構的聲明稿活動與三類題目：口徑外追問、連續追問、資料沒寫。**人名、事件全部虛構。**
- `honest_no_data` 的定義要改：以前是「答案裡要出現『沒有資料』這類字」，改成「沒有編造內容，而且狀態被正確判成 `no_data`」。
- 新增一項硬性檢查：口徑外的題目，回覆裡不能出現「我沒有資料」「無法確認」「無可奉告」。
- `tools/line-persona-sim/` 加一位「追問型記者」。
- 截圖那兩句（換成虛構人名）就是驗收題。

**驗收：** 用虛構的聲明稿活動，在 1:1 與群組各問那兩句。第一則有接住、有界線、有「已轉告」而且管理員真的收到推播；第二則比第一則短、沒有重複同一套話；兩則都沒有接官網新聞；`qa_log` 兩列的 `answer_status` 都是 `no_data`；後台「疑似答不出來」數得到這兩題。評測跟基準比沒有退步。
