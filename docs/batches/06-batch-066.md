### 批次 66：媒體訓練改成用講的（2026-09-16）

**回報的原話**：「主管問答訓練那邊 有可能改成語音問答方式嗎 這樣主管就不用打字
直接講 比較符合真實狀況 你再根據他講的內容來打分數」。

需求全部落在**輸入端與評分端**：主管用講的作答，AI 依他講的內容評分。做完之後
`/training` 預設就是語音，打字變成備選。

#### 一、三層退路，任何一層垮掉都練得完這一場

語音這條路上會壞的地方比打字多得多（沒權限、沒麥克風、不是 HTTPS、瀏覽器不支援、
後端沒設金鑰、辨識服務當掉），每一種都不能讓主管卡在半場：

| 層 | 走哪條 | 什麼時候輪到它 |
|---|---|---|
| ① | 錄音上傳 → 後端 STT（`mode: 'transcribe'`） | 正常情況。品質最好，而且會把活動知識庫前 300 字當詞彙提示餵進去，專有名詞才不會被聽成別的字 |
| ② | 瀏覽器的 `webkitSpeechRecognition` 即時辨識 | 後端沒設 `OPENAI_API_KEY`、或轉寫失敗。它平常只負責「邊講邊出字幕」當視覺回饋，這時候直接頂上來當逐字稿 |
| ③ | 打字 | 麥克風拿不到、或主管自己按「改用打字」。這條**永遠留著**，而且會說清楚為什麼退回來 |

**逐字稿一律先攤開讓主管改過再送出。** 辨識一定會有錯字，尤其是單位名與技術名詞；
沒得改的話，他會看著 AI 在評一段他沒講過的話。這一條沒有例外，三層都一樣。

#### 二、口說要用口說的標準評，不是把書面標準套上去

同一段話，寫出來跟講出來是兩件事。`buildEvaluatePrompt()` 在語音場次多帶四項：

1. **可引用性** — 台灣電視新聞一則受訪片段大約 8–15 秒（約 30–60 字）。講了 90 秒
   卻沒有一句單獨剪出來能成立，這段訪問對記者等於沒有素材，最後被剪出去的往往是
   主管最不想被放大的那句。評語因此多一行「可直接引用的一句」。
2. **結論先行** — 口說沒有標題也沒有段落，記者聽到的第一句就是導言。
3. **長度控制** — 太長剪不到重點、容易被斷章取義；太短沒有內容可寫。
4. **贅詞與口頭禪** — 「嗯」「那個」「就是說」，書面看不到，逐字稿一字不漏。

還有一條是**不准扣的分**：逐字稿是機器聽出來的，「工研院」被聽成「工業院」是辨識
的問題，不是主管講錯。不明講，訓練師會把它當口誤扣分，主管看到評語只會一頭霧水。

秒數、字數、語速（字／分）由 `describeSpeech()` 量好一起送進去——這是語音模式才拿
得到、而且真實媒體訓練一定會看的數字。作答泡泡下面也會標「用講的 · 0:42」。

`mode: 'reporter'` 在語音場次同時要求問題**短、口語、最多兩句**：問題一長，主管得先
在腦中整理題目才答得出來，練到的是閱讀理解，不是臨場反應。

#### 三、四件「不會報錯的錯」，全部擋在程式裡（CLAUDE.md 第 2 條）

這批新增的出口，每一個都踩在這個專案踩過四次的同一個形狀上：

1. **STT 吐簡體字。** Whisper 一族對中文預設就輸出簡體，給 `language: 'zh'` 也一樣。
   這不是「模型偶爾沒照做」，是**每一次都這樣**——而逐字稿會直接顯示在主管眼前、
   還跟著送進評分。`scrubTranscript()` 出口強制轉繁。
2. **靜音幻覺。** Whisper 收到無聲或純雜訊時會吐訓練資料裡的 YouTube 字幕殘留
   （「請不吝點贊 訂閱 轉發 打賞支持明鏡與點點欄目」「字幕由 Amara.org 社群提供」）。
   麥克風沒開的時候，畫面就會冒出這種句子被當成他的回答。同一支函式一併清掉，
   清完是空的就提示重錄。⚠️ 規則寧可漏擋也不准誤刪——主管真的講了「我們會持續
   **訂閱**這份產業報告」被挖掉，比留一句雜訊嚴重得多，測試裡有這一條。
3. **「按了錄音但其實沒收到聲音」。** 系統把麥克風靜音、或選到一支沒接的裝置，
   `MediaRecorder` 照樣產出一個有長度、內容全空的檔案，完全不會報錯。只能自己用
   `AnalyserNode` 量音量：畫面上那條會動的量表就是唯一的徵兆，講了 5 秒還沒有音量
   就當場提示，不要等他講完兩分鐘才發現整段是空的。
   —— 這是 CLAUDE.md 第 4 條（「送出成功」不等於「使用者看得到」）的同一個道理：
   **「開始錄音成功」也不等於「真的錄到聲音」。**
4. **`api/training.js` 的回覆以前完全沒接 `toTraditionalTW()`**，只靠 prompt 裡那句
   「不得出現簡體字」。順手補上——語音場次尤其不能漏，逐字稿跟評語會一起出現在
   同一個畫面上。為此把轉換表從 `api/line.js` 搬到 **`lib/zh-tw.js`**（`api/line.js`
   照樣 re-export，外面既有的 import 一行都不用改），以後任何新出口都接得上。

#### 四、踩到的坑

- **Gemini 吃不下 webm。** Chrome／Edge／Android 的 `MediaRecorder` 預設就是
  webm（opus），所以 Gemini 只能當 Safari／iOS（mp4/aac）那條路的備援，不能當主力。
  `pickTranscribeEngine()` 因此要看格式決定，不是只看有沒有金鑰。
- **Chrome 的 `SpeechRecognition` 講到一半停頓幾秒就會自己 `onend`**，`continuous = true`
  也擋不住。要在 `onend` 裡判斷「還在錄音就馬上接回去」，不然後半段整個不見。
- **錄到一半按「改用打字」會跳出逐字稿確認畫面蓋掉剛切過去的介面**——`stop()` 一樣
  會觸發 `onstop`。加了 `abandonRecording` 旗標區分「講完了」與「不講了」。
- **`multipart/form-data` 不要自己設 `Content-Type`。** boundary 要讓 `fetch` 自己帶，
  手動設會讓整個 form 解不開，而 OpenAI 回的錯誤訊息只會說「檔案格式不對」。
- **測 prompt 字串本身 ≠ 測模型輸出的格式。**（寫測試時真的撞到）前端靠
  `---評分---`／`---下一題---` 切分回覆，我一開始拿 prompt 去對那條 split regex，
  結果永遠多切一刀——因為 prompt 裡本來就有一句「分隔線請一字不差照抄（『---評分---』
  『---下一題---』）」，它自己就長得像分隔線。改成照格式模擬一則回覆再切，才是真的
  在驗「語音模式新增的『可直接引用的一句』會不會讓前端切錯」。

#### 五、刻意沒做：AI 記者「出聲」提問

真實記者會上記者是用講的，所以「AI 記者把問題念出來」看起來是這個需求的下一步。
這一版沒做，原因不是技術，是 **CLAUDE.md 第 3 條**：這支專案只有一種聲音，就是
`tools/guide-video/voice/` 裡那一個（朱朱在 Vidnoz 挑的 HsiaoYu）。而那個聲音是
**手動匯出 + `cute.py` 離線加工**的流程，沒辦法在 runtime 即時合成一句新的話；
真要讓記者出聲，只有兩條路，兩條都要先問過朱朱：

- (a) 破例讓「AI 記者」這個角色用另一個語音（瀏覽器內建 `speechSynthesis`，零成本，
  但就是第 3 條說的「另外挑語音」）；
- (b) 接一家即時 TTS，並由朱朱挑一個「記者的聲音」，比照米亞的方式定下來。

從需求本身看，主管要的是「不用打字」，重點在輸入端；問題用看的不影響練習。所以這
一版先把該做的做完，出聲這件事留給他決定。

#### 六、人類要做的事

到 Vercel → Settings → Environment Variables 設 **`OPENAI_API_KEY`**（`api/geo.js`
本來就有這個變數，設過就不用再設一次），然後 Redeploy。沒設也能用——會自動退到
瀏覽器內建辨識（上面的第 ② 層），只是專有名詞的辨識率差一截。
轉寫模型可用 `OPENAI_STT_MODEL` 覆寫，預設 `gpt-4o-transcribe`。

#### 七、驗證

`npm test` 全部通過（新增 `test/training-voice.test.mjs`，45 項）。除了純函式，
它也把 `public/training.html` 撈出來檢查：JS 裡 `getElementById` 用到的 36 個 id
在 HTML 裡都真的存在（打錯字不會有任何紅字，只會讓按鈕按了沒反應），以及三層退路、
麥克風關閉、音量偵測、`spoken`／`duration` 這些關鍵接線都還在。

### 批次 67：媒體訓練要求「30 秒到 1 分鐘講完重點」（2026-09-16）

**回報的原話**：批次 66 的語音作答做完之後，主管追加一句「然後盡量 30 秒到 1 分鐘
講完重點的內容，要求主管」。

這是把語音演練從「能用講的」推進到「練一件具體的事」。**30–60 秒不是隨便訂的**：
電視新聞一則受訪片段只用得到 8–15 秒，平面記者要的是一句能下標的話。30 秒以下常常
是重點還沒鋪完就收；超過 1 分鐘，記者開始挑不出要用哪一段——而**挑的人不是主管**，
最後被剪出去的，往往是他最不想被放大的那句。所以這個區間的上限比下限重要得多。

#### 一、要做在兩個地方，只做一邊等於沒做

| 時機 | 做什麼 | 為什麼非得在這個時機 |
|---|---|---|
| **講的當下** | 計時器跨過 30／60／90 秒就換顏色與提示語（「重點時間，可以準備收尾了」→「已經超過 60 秒，請收尾」→「太長了，記者會抓不到重點」） | 真實的媒體訓練師是在旁邊比手勢示意收尾，不是事後寫檢討報告。講完才被告知「你講太久了」，那一題已經練壞了 |
| **評分時** | 長度變成獨立評分項，`buildEvaluatePrompt()` 要求**每一題都要講到**；超過 60 秒要在「改進建議」第一條點名，並在「建議更好的答法」給一個真的講得完的版本、末尾標上大約幾秒 | 當場的提示只是訊號，真正告訴他「哪一段可以砍」的是評語。沒有這一半，他知道自己超時卻不知道該怎麼改 |

回覆格式因此固定多一行「本題長度：X 秒（目標 30–60 秒）—（講評）」，每一題都看得到
自己落在哪，不必自己去對照。作答泡泡下面超時的那題會標紅，整場回顧時一眼看得出來。

#### 二、三個容易寫反的地方

1. **「60 秒內講完重點」不是「講滿 60 秒」。** prompt 裡有一條專門擋這件事
   （`不要建議他把話拉長`）。沒寫清楚，訓練師看到「目標 30–60 秒、他講了 20 秒」
   會很自然地建議他多講一點——但一個 20 秒而精準完整的回答是**好答案**，不該被改壞。
2. **講得短不扣分。** `describeSpeech()` 對 short 區間的描述刻意寫成「若重點已經完整，
   這是好事；請確認他沒有漏掉關鍵資訊」，而不是寫成扣分理由。要抓的是漏掉關鍵數字
   或時程，不是秒數不夠。
3. **錄音硬上限刻意留在 `MAX_REC_SECONDS = 150`，沒有跟著降到 60。** 一到 60 秒就
   自動切斷，主管永遠練不到「自己收尾」這件事——而記者會現場不會有人幫他按停止。

#### 三、前後端的秒數必須是同一個數字

`public/training.html` 的 `TARGET_MIN_SEC`／`TARGET_MAX_SEC`／`TOO_LONG_SEC` 要跟
`api/training.js` 的同名常數對得起來。不一致的後果很難查：主管**照著畫面準時收尾，
卻被評語說超時**，而兩邊都不會報任何錯。`test/training-voice.test.mjs` 因此直接從
HTML 裡把這三個數字撈出來跟後端比對——跟 `test/kb-limit.test.mjs` 對前後台字數上限
做的事情一模一樣。

#### 四、驗證

`npm test` 全部通過。`test/training-voice.test.mjs` 新增第 3b 節（區間邊界：29／30／
60／61／90／91 秒）與前後端常數一致性，並檢查「當場提示」那幾條接線還在，
包括一條優先序：**沒收到聲音的警告要壓過時間提示**——麥克風沒開比講太久嚴重得多。

#### 五、另外加了一支瀏覽器驗證：`tools/training-voice-check.mjs`

靜態檢查證明不了「載進瀏覽器之後跑不跑得起來」。這支用 playwright 開一顆 Chromium、
餵一段假的麥克風訊號，把整條路跑一遍：載入 → 開始 → 錄音 → 分區提示 → 停止 →
逐字稿確認 → 切換打字，順便檢查有沒有 JS 執行期錯誤、錄完麥克風有沒有真的釋放。

**刻意不放進 `test/`、也不進 `npm test`**——它需要 playwright 跟一顆 Chromium，而
`test/` 裡每一支都是「拿到原始碼就跑得起來」的（見 `test/test-guide-video.mjs` 開頭
那段「刻意不依賴 ffprobe」）。所以比照 `tools/guide-video/rec.mjs` 放在 `tools/`。

第一次跑就抓到兩件事，兩件都值得記下來：

1. **音量要看整段峰值，不是瞬間值。** 一開始斷言寫成「音量條的寬度 > 0」，結果拿到
   0%——因為讀到的那一刻剛好落在假麥克風 beep 的間隙。程式本身是對的（`peakLevel`
   存的是整段最大值，實測 0.76）；錯的是斷言。這反過來印證了設計：**用瞬間值判斷
   「有沒有收到聲音」，講話的每一次停頓都會誤報。**
2. **音量條在桌面寬度下被拉滿整行**（1100px 以上）。它顯示的是瞬間音量，會跟著每個
   音節劇烈跳動——一條上千 px 寬的東西在旁邊狂閃，反而會把注意力從計時器上拉走。
   改成 `flex: 0 1 200px`，手機上照樣自適應。

### 批次 68：主管實測語音演練，三個問題（2026-09-16）

批次 66／67 上線後主管在 iPhone 上實跑第一題，截圖回報。三個問題，其中一個的
根因很值得記下來。

#### 一、整個頁面是放大的——根因是一個 14.4px 的輸入框

截圖的症狀：header 被 iOS 狀態列蓋住、進度條的「訓練進度」左邊被裁成「練進度」、
右邊的「1 / 5 題」也被裁掉。一開始以為是 flex 版面爆掉（`#messages` 少了
`min-height: 0`），用 iPhone 尺寸去重現——**重現不出來**。`#messages` 有
`overflow-y: auto`，規範上 `min-height: auto` 本來就會解析成 0，那條路是錯的。

真正的原因是：**iOS Safari 對 `font-size` 小於 16px 的輸入框，一 focus 就會自動
放大整個頁面，而且放大後不會自己縮回來。**

開始畫面那個「您的姓名／職稱」欄位是 `font-size: 0.9rem`＝14.4px。主管開始訓練前
點了一下那一欄，iOS 就把整頁放大了，然後**整場訓練都在放大狀態下進行**——左右被裁、
header 滑到狀態列底下。

這又是一個典型的「不會報錯的錯」：CSS 完全合法、桌面瀏覽器完全正常、Chromium 模擬
iPhone 尺寸也一切正常，只有真的 iOS 裝置會這樣。修法是把字級拉到 16px，**不是**用
`maximum-scale=1` 禁止縮放——那會害到真的需要放大來看的人。

`test/training-voice.test.mjs` 因此多一條：頁面上每一個輸入框的字級都不得小於 16px。

#### 二、語音場次的第一題吐出兩大段——兩條 prompt 規則打架

批次 66 在 `buildReporterPrompt()` 的語音分支寫了「口語、直接、**最多兩句話**、
不要分段」，但底下那條通用的開場指示還是舊的：「先自我介紹，**說明今天想深入
了解的角度**，然後提出第一個問題」——三件事。

兩條規則直接矛盾，模型選了比較具體的那一條（開場），於是第一題變成落落長的兩段。
語音演練練的是臨場反應，題目一長，主管得先讀完一整段才開得了口，練到的變成閱讀理解。

修法是**開場指示也分兩版**：語音版只要一句自我介紹，然後直接問，明文寫出「不要說明
你的採訪角度、不要鋪陳背景——現場記者搶到麥克風時不會這樣做」。

教訓：在 prompt 裡加一條限制時，要回頭檢查有沒有既有的指示跟它打架。加的那一條
通常寫在前面、比較抽象，而舊的那條寫在後面、比較具體——模型會聽後面那個。

#### 三、「伺服器的語音辨識沒有啟用」每題都跳，還把秒數蓋掉

#### 三、誠實邊界：同業線是「提及率」，不是能見度指數

能見度指數 ＝ 提及 45 ＋ 位置 20 ＋ 自家網域被引 20 ＋ 有具體內容 15。
**後面三項判官只對工研院判**，題目就是這樣設計的；對照機構只有「有沒有被點名」
這一個事實。硬要幫對照機構湊一個 0–100 分數，就是拿自己編的數字去跟自己比，
看起來很專業，實際上一被追問就垮。

所以同業對照一律用兩邊都真的量到的那一件事：**提及率（%）**。這也代表它跟能見度
指數走勢**不能疊在同一組 Y 軸上**，所以是獨立一張圖、獨立一條座標軸、標題與說明都
寫明單位，而不是在原圖上多加幾條線。

#### 四、又是第 2 條原則：擋在程式出口，不是寫在說明文字裡

這次「絕對不能發生」的事是：**在沒有資料支撐的情況下，畫面上長出一個看起來像結論的
東西**。它有兩個版本，出事的方式一模一樣——有人截圖傳給記者，而且錯在我們自己：

1. 只掃了四天，KPI 卡片卻顯示一個向上箭頭
2. 滾動窗內只有一筆樣本，同業圖上卻畫出一個 100% 的尖峰

擋法都在資料出口，不在畫面邏輯，也不在說明文字：

- `selfTrend()` 樣本不足時，`current`／`baseline`／`delta` **一律回 null**——
  不是讓前端自己判斷要不要顯示，是根本不給它數字，前端想畫也沒得畫
- `buildPeerSeries()` 滾動窗內有效樣本 < 3 筆時，那個點回 `null`（斷線），不畫 0% 也不畫 100%
- 區間內被提到不到 3 次的機構，不會被拱成「對照基準」
- 掃失敗的 run（`score` 是 null）不算進分母。算進去的話所有機構的提及率會一起被
  稀釋，看起來像大家同時變差——那其實是我們的爬蟲壞了，而這種誤會沒有人查得出來

另外兩個刻意保守的設計，寫在 `lib/geo-benchmark.js` 裡：30 天基線**含**本週
（窗重疊會讓漲跌被自己拉平，寧可少報一次漲）；死區 ±2 分（單次查詢本來就有隨機性，
1 分的差距講「上升」是在編故事）。這個標記是「一眼看個大概」，**不是統計檢定**——
要對外宣稱某場活動真的把數字推上去，看的是一頁報告那邊以「天」為群集的 bootstrap
信賴區間。

### 批次 70：主管訓練模式——真實媒體、依身分出題，外加四個會安靜出事的 bug（2026-09-17）

需求原話：「盤點如何更好用，讓主管們願意用他，並且減少 bug、開始時會先問主管是誰，
並針對她是誰來準備對應題目？然後媒體名稱要用真實的台灣媒體，不要用假的」。

#### 一、為什麼主管不太想用——盤下來的三件事

1. **不知道今天是誰來訪。** 舊 prompt 寫的是「虛構媒體名稱」，模型每次自己編一家。
   真實的媒體訓練，第一件事就是告訴受訓者「今天來的是哪一家」——因為《工商時報》
   跟《公視》想要的東西完全不同，該準備的話也不一樣。編出來的媒體，練起來不像真的。
2. **題目對誰都只有七分準。** 開始畫面那個「姓名／職稱」欄位只寫進演練紀錄，
   **從來沒有進到 prompt**。所以不論院長還是計畫主持人，拿到的是同一批題目。
3. **一次網路中斷就毀掉整場。** 見第三節。

#### 二、真實媒體：13 家，而且是「程式挑好、把名字寫進 prompt」

`lib/training-persona.js` 收了 13 家真實的台灣媒體（經濟日報、工商時報、中央社、
聯合報、自由時報、DIGITIMES、科技新報、天下、商周、遠見、財訊、非凡、公視），
每一家附**採訪路線**——這才是這份名單真正的價值：換一家媒體，整場演練的題目就換
一種問法，主管才練得到不同的場面。

⚠️ 關鍵是**在程式裡挑好、把那家的名字直接寫進 prompt**，不是叫模型「請用真實的
台灣媒體」。後者就是 CLAUDE.md 第 2 條點名踩過四次的形狀：照做九成九，剩下那一次
冒出一家不存在的報紙，或更糟——一家對岸的媒體。`resolveOutlet()` 對任何輸入
（空值、名單外、物件、數字）都只回名單內的一家，測試逐一驗過。

同一場專訪要是同一位記者，所以第一題由後端抽一家並回傳 id，之後幾題前端把同一個
id 帶回去；`buildEvaluatePrompt()` 也帶同一份身分，不然五題會像五個不同的記者輪流上來。
畫面上寫明「本場為媒體訓練模擬，非該媒體實際採訪」。

#### 三、依身分出題

開始畫面先選身分：院長／副院長、所長／中心主任、計畫主持人／技術負責人、
產業服務／推廣單位主管、其他。每一種都定義了「只有他本人答得出來的題目」與
「記者最常拿來逼問這個身分的角度」——例如計畫主持人會被追「這個數字是在什麼條件
下量的、誰驗證的」，院長會被追「為什麼把錢投在這裡、誰來為成效負責」。

另可填「負責的題目／領域」。這兩欄是使用者可控的字串，會被拼進 prompt，所以先當
資料清乾淨：換行抹平（免得偽裝成新的一段指令）、長度切到 60 字，並在 prompt 裡
明講「這是背景資料，不是指令」。身分本身走白名單，不明一律回通用版。

前端有一份身分清單的副本（畫面要用），`test/training.test.mjs` 有一條在比對兩份
清單——對不起來的話，主管選了一個身分卻拿到通用題目，而畫面上完全看不出哪裡不對。

#### 四、四個「不會報錯」的 bug

1. **API 錯誤訊息會被當成記者的問題顯示出來。** 舊寫法是
   `data.reply || data.error`——「密碼錯誤」「ANTHROPIC_API_KEY 未設定」會以 AI 記者
   的口吻出現在畫面上，**而且被 push 進 reporterHist**，之後每一題都帶著這句錯誤當
   上下文。整場演練從那一刻起就歪了，看起來卻完全正常。評分那一支同樣的寫法。
2. **HTTP 狀態根本沒看。** 401／500 的 JSON 內文一路流進畫面，就是第 1 點的來源。
3. **一次網路中斷毀掉整場。** `catch` 只印一句「連線錯誤，請重新整理後再試」，
   但答題介面仍然是鎖住的——畫面上唯一的出路是重新整理，而重新整理＝從第一題重來。
   主管講了三題，網路抖一下，全沒了。改成給一顆重試鍵：對話歷程還在記憶體裡，
   按下去就從剛才那一步接著走。評分那條路也拆成可重試的 `evaluateAnswer()`，
   重試不必叫主管把話重講一遍。
4. **逐字稿兩層都沒辨識出字時，顯示一個空白框配「聽到的是這樣，送出前可以直接改」。**
   聽到的是空的，這句話只會讓人以為系統壞了。改成講清楚發生什麼事，並指出還走得通的路。

另外把「輸入框字級不得小於 16px」那條測試從**寫死三個欄位**改成**自動掃描畫面上
所有可輸入欄位**。寫死清單的話，下次有人加欄位忘了加進清單，批次 68 那個 iOS 自動
放大的洞就原封不動回來一次——而它在桌面瀏覽器與模擬器上都完全正常。

#### 五、「不接 GPT 省錢」的實際後果，以及一個順手的修正

主管交代不接 OpenAI 省錢，所以轉寫只剩免費的 Gemini。但 **Gemini 吃不下 webm**，
而前端 `pickRecMime()` 的第一順位偏偏就是 webm——等於在 Chrome／Android 上，
就算 `GEMINI_API_KEY` 設好了也永遠用不到伺服器辨識，一路退到瀏覽器即時辨識。
這件事不會報錯，只會讓逐字稿品質莫名其妙比 iPhone 差。

改成先問 `audio/mp4`、`audio/ogg`，都不支援才退回 webm（實測 Chromium 141 支援
`audio/mp4`，實際錄一段驗過檔頭確實是 MP4 的 `ftyp`）。mp4 用 AAC 的位元率要拉到
64 kbps，32 kbps 會糊掉、逐字稿錯字變多；64 kbps × 上限 150 秒約 1.2 MB，仍在
`MAX_AUDIO_BASE64` 之內。

⚠️ **還沒實測**：Chromium 的 mp4 裡裝的是 Opus 不是 AAC，Gemini 收不收這個組合不確定
（它的文件列的是 aac／ogg／wav／mp3／flac）。不確定也值得換，因為只有上檔沒有下檔——
讀不懂的話後端回 502 帶 `fallback:'browser'`，前端照樣用瀏覽器那份，跟現在的 webm
一模一樣；讀得懂就白賺一份品質更好的辨識。要確認：設好 `GEMINI_API_KEY`，用 Chrome
錄一題，看逐字稿確認畫面還會不會跳「伺服器的語音辨識還沒啟用」。

#### 六、順手挖到的：繁體防線自己有一個安靜的破口

寫測試時被 `toTraditionalTW()` 標記，追下去發現 `lib/zh-tw.js` 的 `S2T_CONTEXT`
（后／发／准／里 這四個歧義字看鄰居決定怎麼轉）有一個真的會漏字的寫法：

```js
return (keepPrev.includes(prev) || keepNext.includes(next)) ? ch : to;
```

字串開頭時 `prev` 是空字串，而 **JS 的 `String.includes('')` 恆為 `true`**。
所以這四個字只要剛好落在整段文字的**頭或尾**，就一律被當成例外、完全不轉。

其中「发」最嚴重：它在繁體中文裡根本不是一個字（發／髮才是），漏掉就是**簡體字
真的送到記者眼前**。實測 `toTraditionalTW('请勿转发')` 回的是「請勿轉发」。

這是整個專案第 1 條規則的強制出口，而它自己有一個破口，而且是那種「九成九的句子
都不會踩到」的破口——所以一直沒被發現。修法是先確定鄰居真的存在再查例外表。
`test/test-zhtw.mjs` 補了兩組：開頭／結尾的歧義字要轉，以及原本就該保留的 13 個例外
（批准、皇后、公里、頭髮⋯⋯）一個都不能壞。

#### 七、還沒做的（建議，依價值排序）

1. **加「3 題快速演練」。** 現在固定 5 題。主管的時間是零碎的，門檻降低才會有第二次。
2. **終畫面要帶得走。** 現在只有平均分和一句「請參考各題的評分建議」。
   建議加「這場最該改的三件事」與可複製的重點——主管離開頁面就什麼都不剩。
3. **看得到上次練了什麼。** `training_log` 已經在存，但畫面上沒有回顧。
4. 分議題的題庫輪替：同一場活動練第三次，題目重複感會出現；身分＋媒體輪換只緩解了一部分。

#### 八、驗證

`npm test` 全部通過（`test/training.test.mjs` 新增第 4–8 節、`training-voice.test.mjs`
新增第 10 節與自動掃描字級、`test-zhtw.mjs` 新增開頭結尾那兩組）。

#### 一、一張「什麼都沒發生」的截圖，回答了上線時沒驗到的問題

主管上線後隨手測了一下：按錄音、沒出聲、停止。截圖上那行字是

> 講了 0:04，比目標短——重點講完就好，短不是問題｜**這段錄音裡沒有聽到說話的內容。**

他的結論是「沒出聲所以沒字，正常」——對，但這句提示的**來源**比內容重要。
「這段錄音裡沒有聽到說話的內容」只從 `res.ok && data.empty` 這一條路來，而後端的
`empty: true` 只在 `transcribeAnswer()` 的 **try 區塊成功之後**才回得出來：

```js
const raw = await transcribeWithGemini(decoded.buffer, decoded.mime, hint);  // 沒有 throw
const text = scrubTranscript(raw);
if (!text) return res.status(200).json({ text: '', empty: true, engine });
```

所以這一次至少確定兩件事：

1. `pickTranscribeEngine()` 挑到了引擎（不是 null）——代表送上去的 mime 不是 webm，
   **批次 70 把錄音容器改成優先 mp4 那個改動生效了**
2. `transcribeWithGemini()` 沒有丟出例外——**Gemini 收下了「MP4 容器裝 Opus」這個組合**

批次 70 在 PR 上標註「尚未實測」的那個風險，答案是通的。不是推論出來的，是那條錯誤
路徑（502 → `fallback:'browser'` → 顯示「伺服器的語音辨識還沒啟用」）**沒有被觸發**。

還沒驗到的是「真的講話時辨識得準不準」——那要實際錄一句帶專有名詞的話才知道。

#### 二、順著那張截圖修掉的三件事

**① 空逐字稿不要評論長度。** 「比目標短——重點講完就好，短不是問題」是在評論一段
根本不存在的回答，還跟後半句「沒有聽到說話的內容」自相矛盾。

⚠️ 但**不能反過來把批次 68 的規則弄掉**：有逐字稿的時候，秒數與長度評語永遠要顯示、
不能被提示訊息蓋掉——那正是這一版在練的東西。所以判斷式是 `hasText && pendingSeconds >= 1.2`，
兩個方向相反的規則同時成立。

**② 空的時候要給下一步。** 原本只說「沒有聽到說話的內容。」就結束了，沒講該怎麼辦。
加上「請按『重錄』再講一次，或直接在下面打字。」

**③ 順手發現的矛盾：後端說沒聽到、瀏覽器其實聽到了。**

```js
if (!text && live) { text = live; if (!note) note = '以下是瀏覽器聽到的版本…'; }
```

`if (!note)` 代表 note 已經是「沒有聽到說話的內容」時**不會被換掉**——於是畫面上
框裡明明有字，上面卻寫著沒聽到，主管只會以為系統壞了。改成那句話不再成立時就換掉
（「伺服器辨識還沒啟用」那句要留著，它講的是另一件事，資訊量比較大）。

#### 三、測試：從「比對程式碼長相」換成「真的跑起來」

批次 68 留下的那條守秒數的斷言原本是用正規表示式比對原始碼：

```js
ok(/if \(pendingSeconds >= 1\.2\) head\.push/.test(js), '秒數不會被提示訊息蓋掉');
```

這次改判斷式，它就失準了——而它守的是一個真的踩過的坑。改成把 `<script>` 抓出來配
假 DOM 真的跑 `showTranscript()`，驗畫面上那行字的內容（同
`test/backend-event-modal.test.mjs` 的做法）。八個案例，兩個方向的規則都釘住。

⚠️ 寫這支測試時自己踩到一個值得記的坑：**沙盒少給一個 `FileReader`，
`transcribeBlob()` 就丟 ReferenceError 被 catch 接走，測試一路綠燈、卻根本沒走到
要測的那條路。** 是因為斷言的失敗訊息印出了實際文字（「語音辨識連線失敗…」）才發現的。
假 DOM 測試要盡量讓斷言把實際值印出來，不然「測過了」跟「測到了」分不出來。

2. 媒體訓練系統：使用流暢度、是否有 bug、易用性與實用性增強，因為想要在下場活動正式採用」

批次 57 盤的是「已讀不回」。這次換兩個角度：LINE 把**記者真的會打的一百七十句話**
（現場事務、刁鑽題、收尾語、口語錯字、英文）整批丟進規則層，看每一句落到哪條路；

#### LINE 一、後台填的時間地點，答題的模型從來沒看過

記者綁定一場之後最常問的現場事務：「幾點開始」「在哪裡辦」「開始了嗎」「新聞聯絡人
是誰」。後台明明有這四個欄位（events F、L、M、O），但：

- `rowToEvent()` 根本沒讀 L（時間）、M（地點）欄
- `buildSystemPrompt()` 只放知識庫全文，日期與聯絡人也沒有交給模型

新聞稿內文沒寫時間地點時（活動後發的新聞稿通常不寫），模型只能照規則說「這部分我沒有
資料」，接著 NO_DATA 標記還會拿「活動時間」去官網新聞中心補查一輪。**資料就在我們自己
的表裡，卻繞一大圈說不知道**——這就是「會被問倒」最典型的樣子。另外模型不知道今天幾號，
「開始了嗎」「還有多久」答不出來，也可能把辦完的活動講成未來式。

修法：`lib/prompt.js` 新增 `formatEventBasics()`，組一段【活動基本資料】（日期＋星期＋
相對今天幾天、時間、地點、新聞聯絡人、現在時間），LINE 與網頁版問答都接上。

- 放在**第二個、不吃快取的 system 區塊**：現在時間每分鐘在變，放進第一塊會讓每一題都
  重建快取；`buildSystemPrompt()` 本身一個字沒動（檔頭那條「網頁版逐 byte 相同」照舊成立）。
- F 欄只認「手動填的日期」：沒填日期時系統寫進去的是建立時間戳記（「2026/6/18 下午
  11:06:04」），那不是活動日——帶著時間的一律不採用，測試有釘。
- 活動前（邀請函模式）照樣給：日期、時間、地點、聯絡人本來就是「尚未舉行的場次只能
  提供」的那幾項（第 6 節）。

#### LINE 二、「有新聞稿嗎」——批次 61 的症狀，規則層那條路

批次 61 修的是 `routeIntent()` 把「新聞稿」判成全站新聞。但規則層在更前面：
`isLatestNewsQuestion()` 會吃下「有新聞稿嗎」「給我新聞稿」「新聞稿呢」「新聞稿發了嗎」
（扣掉核心詞與語助詞剛好一個字不剩），在 `handleMetaIntent()` 直接送去官網最新五則，
連 `routeIntent()` 都輪不到。記者掃了某一場的 QR code，在那一場裡問「有新聞稿嗎」，
拿到的是工研院最近的五則新聞。

修法：`lib/menu.js` 新增 `isOrgWideNewsAsk()`——句子裡有指向全院或一段時間的字（工研院、
最近、最新、這個月、有哪些…）才是在問全站新聞；沒有的話，綁定中就交給這一場的
`answerQuestion()`（這場沒有新聞稿時它自己會老實說、給聯絡人；活動前會說正式新聞稿當天
發布）。沒綁定時不受影響。1 對 1 與群組共用 `handleMetaIntent()`，改一處兩邊都到。

#### LINE 三、「謝謝米亞」被當成主題詞複誦

沒綁定時（剛問完產業趨勢／技術——那兩條路不綁場次，或回首頁之後），記者說一聲
「好的謝謝」「謝謝米亞」「了解」「收到謝謝」「先這樣」，全部被 `looksLikeBareTopic()`
當成主題詞：「『謝謝米亞』我可以從兩個方向幫您找 🙂」，底下掛著「謝謝米亞的產業趨勢」
「工研院的謝謝米亞技術」兩顆按鈕。正是批次 27 開頭那段警告的形狀，只是這次的例子不是
「天氣如何」。同一批還有「答錯了」「看不懂」「太長了」「測試一下」「哈囉米亞」。

綁定中則是另一種浪費：「謝謝」被送進 Sonnet，回一句不客氣再掛「內容僅供參考」的警語，
還被記進 qa_log 算成一題提問（媒體訓練會從 qa_log 撈「記者真的問過的題目」，六個字以上
的「好的謝謝米亞」也會被撈去當題目素材）。

修法（三層，對應三種位置）：

| 層 | 做什麼 |
|---|---|
| `lib/menu.js detectCourtesy()` | 整句拆成收尾用的字，拆完一個字不剩才算——「謝謝，那成本呢」拆完還剩「那成本呢」，照常問答。`detectMetaIntent()` 第一個判它，回 `thanks`／`ack` |
| `handleMetaIntent()` | 固定回「不客氣 🙂…」「好的 🙂…」，不呼叫模型、不寫 qa_log；綁定中附這場的快速提問 |
| `sendFallbackGuide()` | 職員模式不經過上一層，這裡再認一次；另外新增兩類寫死的閒聊（`repair`：答錯了／看不懂／太長了…；`test`：測試一下） |
| `looksLikeBareTopic()` | 收尾語、閒聊、「哈囉米亞」一律不算主題詞。群組守門也靠這支判斷「剛答完趨勢後的裸名詞追問」，放行「好的謝謝」就等於在別人的群組裡插話 |

⚠️ 「答錯了／太長了」只在**沒綁定**時才用固定回覆。綁定中它們會連同上一輪對話交給
`answerQuestion()`，模型可以真的重答、縮短——那比一句固定的道歉有用。

⚠️ 新增了四句寫死的文案（`COURTESY_REPLIES` 兩句、`CHITCHAT_FIXED_REPLIES` 的 repair、
test）。語氣照批次 64 那條線寫（有溫度、不俚語、不公文），但**請朱朱看過再定稿**——
前幾批的經驗是這種句子要改兩三輪。

#### 媒體訓練 一、打字作答按送出鍵，送出的是「[object PointerEvent]」（最嚴重）

```js
document.getElementById('send-btn').addEventListener('click', submitAnswer);
```

批次 66 把 `submitAnswer()` 改成可以帶參數（語音那條路要傳逐字稿），這一行沒跟著改：
點擊事件物件被當成回答內容，`String(event)` 是「[object PointerEvent]」。主管打好的回答
被清掉，畫面上與送去評分的都是那串字，然後拿一個 0～2 分。

按 Enter 走的是 `submitAnswer()` 不帶參數，所以桌機上測不出來——**偏偏手機上多半是按鍵**。
而打字是語音的最後一道退路（麥克風壞掉、開放空間不方便講），也就是說這條退路從批次 66
起在手機上就是斷的。真的 Chromium 點一下就重現。

兩邊都改：綁定包一層 `() => submitAnswer()`，函式裡只收字串。測試有兩層：靜態擋住舊的
綁法，假 DOM 真的觸發點擊、看送去評分的內容（反向驗證過：改回舊綁法兩條都紅）。

#### 媒體訓練 二、對話歷程的兩個形狀問題

- **第一則是 assistant。** 出第一題時後端送 `[{ user: '請開始。' }]`，前端只記下模型回的
  那一則，於是從第二次請求起歷程開頭少了那則 user。Messages API 文件寫明第一則必須是
  user。後端新增 `normalizeMessages()` 補回同一句，順便合併連續同角色、過濾不是字串的內容。
- **下一題被推兩次。** 評分回覆本身就以「---下一題---＋題目」結尾，前端又把題目單獨 push
  一次，歷程變成 `assistant,user,assistant,assistant,user`——同一題出現兩次、每一輪多送一段。

#### 媒體訓練 三、手機上的版面：對話區只剩兩百多 px
