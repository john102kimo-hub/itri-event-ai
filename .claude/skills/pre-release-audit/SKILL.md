# 上線前盤點

批次 174「上線前一天再盤點」的做法，整理成固定流程。**機器能算的交給程式，需要人判斷的才問人**——不要讓使用者去背清單。

## 第一步：機器檢查（幾秒）

```bash
node .claude/skills/pre-release-audit/audit.mjs
```

它檢查：
- `api/` 的 Function 數（Vercel 免費方案上限 12，一支都不能多）
- 程式讀了、但部署文件沒寫的環境變數（「部署成功但功能沒開」最常見的原因）
- 有沒有敏感檔被 git 追蹤（`.env`、真實問答、私鑰）
- 最新批次紀錄是不是太久沒更新

有 ❌ 就先處理，不要往下走。

## 第二步：跑完整測試（約 5 分鐘）

跟 CI 一模一樣的三輪（`.github/workflows/test.yml`）：

```bash
node .claude/skills/pre-release-audit/audit.mjs --tests
```

三輪是：一般、`SHIFT_DAYS=90`（抓寫死的日期，批次 103 的教訓）、業發處功能開著再跑一輪（既有功能不能被影響，批次 119）。

## 第三步：人工確認（逐項問使用者，已知答案的別再問）

這些程式看不到，要請朱朱或承辦人回答。**一次問一個群組、列出你已經確認過的**，不要丟一整張表：

**A. 對外的東西**
- 這次動到的功能，有沒有同仁實際用手機走過一遍？（測試用假的 Sheets、LINE、模型，真機行為只有人測得到。）
- 記者端看到的文字有沒有簡體字、Markdown 符號（`**`、`#`）、`[[NO_DATA` 殘留？（出口有擋，但要親眼看一次實際畫面。）
- 新增的後台頁面有沒有加進 `vercel.json` 的安全標頭規則？（`test/test-batch110.mjs` 會逐頁檢查，已含在第二步。）

**B. 資料與時間**
- 要上線的活動：必填四項（日期、地點、新聞聯絡人、新聞稿）齊了嗎？→ 用 `new-event-checklist` skill 查。
- 新聞稿**解禁時間**對嗎？活動前有沒有媒體邀請函？（沒有邀請函、一發布記者就問得到新聞稿全文——批次 171。）
- Google Sheets 讀取額度（每分鐘 60 次、全站共用）：活動當天預期同時發問的人數大概多少？

**C. 帳號與金鑰**
- Vercel 上的環境變數是不是都設了（對照 `SETUP.md`）？特別是 `ADMIN_PASSWORD`、`CRON_SECRET`、LINE 那三把。
- Anthropic Console 的每月花費上限設了嗎？企業場有沒有用另一把金鑰（`ANTHROPIC_API_KEY_BUSINESS`）？
- `LINE_ADMIN_USER_ID` 設了嗎？（有人用密語登入時你的 LINE 才會收到通知。）

**D. 出事時**
- 誰在活動當天待命、聯絡方式是什麼？
- 記者截圖回報有問題時，下一步是什麼？（批次紀錄的「回報／根因」就是這樣累積的。）

## 第四步：寫結論

用條列回報：✅ 通過的、❌ 沒過的與建議、⚠️ 需要人決定的。**沒有親自驗證過的就寫「未驗證」，不要寫成通過。** 有改東西就用 `batch-log` skill 記一批。

## 守則

- 只檢查、不修改，除非使用者要你修。
- 不要把真實問答、記者姓名、未發布稿件貼進對話或存進 repo。
