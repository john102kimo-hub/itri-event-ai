# 寫批次紀錄

這個專案的規矩（CLAUDE.md 第 5 條）：每一批改動都要留下「**為什麼**這樣改、踩到什麼坑」。下一個接手的人需要的是原因，不是 git log 上的「改了什麼」。`test/test-docs.mjs` 會擋格式與漏列，所以格式要照著來。

## 步驟

1. **先問記帳工具**（不要自己數編號）：
   ```bash
   node .claude/skills/batch-log/next-batch.mjs
   ```
   它會告訴你：下一個批次編號、要接在哪個檔案後面、最新檔案超過 900 行時要不要開新檔（開新檔要做的三件事它也會列出來）。

2. **把這批的內容寫進去**——接在它指定的檔案最後面，標題格式**一個字都不能錯**：
   ```
   ## 批次 N：標題（YYYY-MM-DD）
   ```
   ・`批次 N：` 用全形冒號；日期是今天，標題結尾的全形括號要有。索引與測試靠這一行抓。

3. **補索引**（標題要跟上一步一字不差，不含 `## 批次 N：`）：
   ```bash
   node .claude/skills/batch-log/next-batch.mjs --index "標題（YYYY-MM-DD）"
   ```
   它會檢查你真的寫了那一章，才補上 `| N | 標題 | [檔名](檔名) |`。

4. **驗證**：
   ```bash
   node test/run-all.mjs docs
   ```

## 內容怎麼寫（照最近幾批的形狀）

這個專案的批次紀錄都長這樣，挑有的寫、沒有的別硬湊：

- **回報／起因**：誰、遇到什麼（盡量引用原話或截圖描述）。沒有人回報就寫為什麼要做。
- **根因**：真正的原因，不是現象。寫到「哪支檔案的哪個判斷為什麼會這樣」。
- **做法**：改了哪些檔案（用 `lib/xxx.js 函式名()` 指路，不要貼大段程式）、為什麼選這個做法。
- **刻意不動**／**沒做**：看起來順手、但故意沒做的事，和原因。這是最容易被下一個人重做的地方。
- **留給下一個人**：還沒解決的限制、要注意的雷。
- **驗證**：哪個測試檔、幾項、修之前是紅的哪幾項。

## 守則

- **只用台灣繁體中文**（CLAUDE.md 第 1 條）。要引用簡體字舉例時，在同一行加上 `zhtw-ok`，否則 hook 會擋。
- **不要**把批次紀錄寫進 `LINE-PLAN.md`——那裡只放長期規格。
- 行號與檔案內容是「當時的狀態」，寫之前自己 grep 現行程式碼，別憑記憶。
- 不要寫進真實記者姓名、提問原文、未發布的新聞稿內容。
