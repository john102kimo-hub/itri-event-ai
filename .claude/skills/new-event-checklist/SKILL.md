# 新增／發布活動檢查表

規則的來源是 `lib/event-status.js`（`eventChecklist()`、`publishBlockers()`、`preEventWithoutInvite()`）。**「還缺什麼」每次算出來都一樣**——所以能查就用程式查，不要憑感覺回答。

## 先查資料（有 MCP 就用 MCP）

如果這個專案的 `itri-event-ai` MCP 伺服器有接上（見 `tools/mcp-itri/README.md`），直接呼叫：

- `list_events`：找到這場的 id
- `event_checklist`（參數 `id`）：回傳必填／加分項目、還缺什麼、能不能發布、發布會有什麼後果

沒有 MCP 的話，請使用者貼上該場活動在後台看到的內容，再用下面的規則手動對照。

## 規則（以 `lib/event-status.js` 為準，改了程式要回來更新這裡）

**必填四項（記者會／一般活動）**——沒填齊「不給發布」，後台、同仁編輯頁、LINE 三個入口都擋（批次 103）：

| 項目 | 怎樣才算填了 |
|---|---|
| 日期 | F 欄是**純日期**（`2026-11-05`）。後面帶時間的是系統寫的建立時間戳記，**不算** |
| 地點 | 有填字 |
| 新聞聯絡人 | 有填字（給記者問「誰負責」「找誰」時用） |
| 新聞稿 | 知識庫**真的寫了東西**。後台新增活動會帶入整份範本，**範本沒動過不算**（批次 103）。例外：活動還沒到、而且有填媒體邀請函，可以先用邀請函，活動當天前補上（批次 173） |

**企業場**（活動類型是企業說明會／技術媒合會／客戶參訪／技術交流會）只要求「內容」與「聯絡窗口」兩項，不要日期、地點。

**加分項（不擋發布，但建議填）**：時間、快速提問（chips）、邀請函（活動還沒到才需要）、照片。

## 發布前要先讓使用者看到的後果

1. **活動前沒有邀請函（批次 171）**：邀請函是活動前唯一的那道牆。有填，活動前米亞只用邀請函回答；**沒填，一發布記者就問得到整份知識庫——新聞稿全文、照片**。不是每場都要邀請函，所以不擋，但**一定要先讓人看過後果再決定**（後台會跳確認視窗，API 沒帶 `ack_no_invite` 會回 409）。你在回答時要主動講。
2. **發布＝讓記者看得到**：公開的狀態是「進行中」與「已結束」；「未發布」與「已封存」不公開。草稿可以先封存再改回來，但同樣要通過必填。
3. **新聞稿解禁**：知識庫如果是還沒解禁的稿，發布前要跟朱朱／承辦確認解禁時間。**這個你看不出來，一定要問。**

## 活動發布後的提醒（讓使用者知道不用自己記）

系統會推 LINE 提醒給活動負責人（批次 177、179）：前一週（沒邀請函）、前一天、當天早上（新聞稿還沒貼）、隔天（沒有照片）。新增活動的人自動成為負責人（批次 180）。要關掉某幾種：環境變數 `REMIND_OFF`。

## 怎麼回覆使用者

用這個形狀，簡短：

```
這場「○○」：
✅ 日期、地點、新聞聯絡人
❌ 新聞稿：還是範本，沒有填
⚠️ 活動 7 天後、沒有邀請函：發布後記者問得到新聞稿全文。要這樣發布嗎？
→ 補完新聞稿就能發布。
```

## 守則

- 只回報事實，**不要替使用者決定要不要發布**。
- 不要把新聞稿全文、記者姓名貼出來；引用時只講欄位名稱與有沒有填。
- 只用台灣繁體中文。
